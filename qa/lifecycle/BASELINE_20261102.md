# Android game simulation remains paused after app switch — baseline evidence

Date: 2026-11-02. Scope: **unchanged original APK** (856,629,249 bytes, SHA-256 `c7df4b880984b9a475b57ee00b41fa5ba6140f4c21e5f688a9188ab1622169c4`). No patched APK has been approved.

## Evidence

- User recordings: return from background continues showing the map and responding to taps, but units and simulation no longer progress; music continues. Recordings were reviewed separately from automatic evidence.
- Donor source at `Vadim170/kam-remake-android@e81c3b7`, `src/KM_MainAndroid.inc`: `AppPause` sets `Game.IsPaused := True` for normal single-player; `AppResume` resumes music and sets `gHostAppActive`, but never resets the game pause.
- Real isolated Android 15 x86_64 (with ARM64 native translation) run [41427684710](https://github.com/constantinepetrov/android/actions/runs/41427684710): full pinned APK installed, data unpacked, native Battle Tutorial smoke passed. Normal tutorial loaded through UI. Actual save-header `TickCount` increased from **230** (`lca0`) to **457** (`lca1`) before the Home event. After Home and returning by Activity launch, the **same PID 4485** remained alive. Screenshots `background/resumed.png` and `background/failed-save-lcb0.png` were pixel-identical (0 differing pixels) even after attempted keyboard/menu interactions. A new save file `lcb0.sav` was not created, so the test ended BLOCKED; there is **no** actual post-background TickCount measurement, and the run is **not** reported green. Evidence archive ID 13133121401 (retention seven days).
- The actual patched `AppPause` and `AppResume` methods, extracted without rewriting from `qa/lifecycle/overrides/KM_MainAndroid.inc`, compiled and executed in FPC 3.2.2 on Ubuntu. All seven scenario groups passed: lifecycle-owned pause, manually paused SP, duplicate callback, replacement game, MP, MapEditor, Replay, menu, music/settings callbacks, tick scheduling. This is host behavior evidence **not** native Android proof.

## Proposed fix

On pause, record whether the active SP game was running and therefore paused by Android; on resume, unpause only that same game. Preserve a player-initiated pause. Re-anchor tick/UI/frame schedules to current clock so the app does not fast-forward through background time.

The override is staged only in `codex/kam-lifecycle-qa`. `master`, draft PR #1, and the old installable APK remain unchanged.
